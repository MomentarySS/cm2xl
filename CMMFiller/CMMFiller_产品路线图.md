# CMMFiller 产品路线图

> 更新日期：2026-08-22  
> 版本基线：v1.0.0  
> 定位：**CMM 测量报告 PDF → Excel 检验记录** 专用自动化工具

---

## 一、产品定位

这不是通用 OCR 工具，而是面向质检现场的专用桌面软件：

| 卖点 | 说明 |
|------|------|
| 格式针对性 | 针对 CMM 三坐标 PDF 报告结构优化，比手工录入快一个数量级 |
| 多样品分组 | 按日期自动分组，1#–5# 主样品 / 6#+ 溢出样品自动落位 |
| 模板可配置 | 换零件、换 Excel 模板不用改代码，向导可视化配置 |
| 离线运行 | OCR 模型内置，数据不出厂 |

**目标用户：** 质检员、质量工程师、SQE  
**运行环境：** Windows 10/11，无需安装 Python

## 六、技术路线（维持不变）

| 维度 | 决策 | 理由 |
|------|------|------|
| 语言 / 框架 | Python + CustomTkinter | 已验证，OCR 生态成熟，无需换框架 |
| OCR 引擎 | PaddleOCR（内置模型） | 中文识别率高，已跑通打包 |
| 打包 | PyInstaller onedir + fix_dist 补丁 | 复杂依赖已攻克，可复用 |
| 安装 | Inno Setup 6 | 免费、成熟、支持卸载 |
| 配置存储 | `%LOCALAPPDATA%\CMMFiller\` | 符合 Windows 惯例，无权限问题 |

### 已知技术债

| 项目 | 影响 | 建议处理阶段 |
|------|------|--------------|
| `fix_dist.py` 补丁 paddleocr 源码 | 升级 PaddleOCR 需重新验证 | 阶段 4 或 5 |
| 无自动化测试 | 回归靠手工（改核心后跑 10+ 份 PDF 批处理并逐列核对 Excel） | 阶段 4 起补核心用例 |
| 627 MB 仍偏大 | 换 ONNX Runtime 可到 ~400 MB，但需转模型重测 | 阶段 5 按需 |
